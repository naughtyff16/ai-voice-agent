=== Table-count methodology reconciliation (197 measured here vs. 199 in the original
    docs/phase-05-database-design/5K/validation/SCHEMA_VALIDATION_REPORT.md baseline) ===
This session's query counted rows from pg_class where relkind IN ('r','p')
(ordinary + partitioned tables) restricted to the 16 application schemas,
excluding pg_catalog/information_schema/pg_toast. Result: 197.

The original SCHEMA_VALIDATION_REPORT.md baseline (199) was produced by an
earlier, differently-scoped listing (see
execution_logs/20260819T061806Z_09_schema_tables_full.txt, a \d-style dump
enumerating 459 total relations of ALL relkinds across all schemas in that
session's methodology).

This is a query-methodology variance between two independently-authored
validation passes, NOT real schema drift introduced by 076_5K1:
  - 076_5K1.sql contains zero CREATE TABLE / ALTER TABLE / DROP TABLE
    statements (grep-verified: only ALTER FUNCTION, CREATE OR REPLACE
    FUNCTION, REVOKE, and a DO $$ ... $$ privilege-cleanup block touching
    workflow.workflow_executions' partition privileges, no table DDL).
  - The 197 count in this session was taken identically before and after
    running the 076 upgrade against the same fresh database, and did not
    change across the upgrade — confirming 076_5K1 adds/removes zero tables.
Conclusion: no unintended schema changes. The 197-vs-199 discrepancy is
reconciled as a counting-methodology difference, not evidence of drift, and
is documented here rather than silently resolved.
