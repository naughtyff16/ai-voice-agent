SCOPE OF THE SECURITY CLAIM (read this before any statement below)
------------------------------------------------------------------------------
Under normal SQL execution with the defined triggers/functions/ACLs enabled, the
tested runtime principals and tested privileged session cannot bypass the
application invariant; deliberate superuser DDL/trigger-disabling actions are
outside the application guarantee.

That sentence bounds every "cannot", "refused" and "enforced" in this file. Two
kinds of superuser action appear below and are always labelled:
  (a) HARNESS TIME TRAVEL - shifting an override window into the past to make a
      row read EXPIRED. No application path can produce such a row (Battery D.7
      rejects a past p_expires_at, and chk_qo_expires_after_start rejects
      backdating expires_at alone - see E.6).
  (b) STRUCTURAL PROOFS - inserting/updating billing.quota_overrides directly as
      the table owner to show that a constraint, not merely a function body,
      holds the invariant.
Neither is an application capability, and neither is presented as one.

PART 8 - WHAT THIS FILE ESTABLISHES, AND WHAT IT DOES NOT
==================================================================================

ESTABLISHED, from live output on PostgreSQL 18.6:
  - ACTIVE_AGENTS admission reads the EFFECTIVE quota, honours an override while
    active, and falls back to the CURRENT baseline on expiry (E.1-E.7).
  - Lowering the effective limit below current usage closes admission and
    destroys nothing (E.8, E.9).
  - The 110_5C2 invariants still hold under the replaced admission body (E.10).
  - Concurrent admission cannot over-admit; concurrent override writes cannot
    produce two current rows (G.1-G.3).
  - created_by cannot be a non-member, a cross-tenant user, or NULL (H.1-H.7).
  - ACTIVE / EXPIRED / SUPERSEDED are three distinct, simultaneously observable
    states, and an EXPIRED current row is not enforced (I.2-I.4).
  - Tenants read their own effective quota without admin privilege, are refused
    across tenants in both directions, are isolated by non-vacuous RLS, fail
    closed without context, and cannot mutate anything (J.1-J.8).
  - Audit records are written in the same transaction as the override, and
    refusals and rollbacks leave neither row (K.10c-K.10e).
  - 111 adds no new BYPASSRLS role and grants no application role write access
    to billing.quota_overrides (K.4, K.6).

NOT ESTABLISHED, and not claimed:
  - Nothing here is a claim about FastAPI-layer behaviour. No application code
    was written or executed in this pass; these are database guarantees that the
    API layer must surface, not replace.
  - Nothing here measures performance, capacity or index efficiency.
  - The EXPIRED state was produced by deliberate superuser time travel on a test
    database. Real expiry has not been observed by waiting for wall-clock time
    to pass; it is inferred from the read-time comparison against NOW(), which
    is what the resolver actually evaluates.
  - The security scope statement at the top of this file bounds every claim
    above: deliberate superuser DDL, disabling triggers, dropping policies or
    altering the functions are outside the application guarantee.
