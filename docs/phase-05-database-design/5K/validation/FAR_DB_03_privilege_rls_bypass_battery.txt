==================================================================================
PART 3 - WHY THE QUOTA INVARIANT IS STRUCTURALLY ENFORCEABLE, NOT MERELY ADVISORY
==================================================================================
  1. voice.agents INSERT is revoked from every runtime role (Part 1 §4, Part 2).
  2. The only remaining INSERT paths are voice.fn_create_agent() and
     voice.fn_clone_agent(), both SECURITY DEFINER owned by postgres (Part 1 §1).
  3. Both call voice.fn_assert_agent_quota_admission() BEFORE their INSERT
     (CONTEXT traces in FAR_DB_02 show fn_create_agent line 23 / fn_clone_agent
     line 54 -> fn_assert_agent_quota_admission line 68 at RAISE).
  4. The two helper functions are reachable by NOBODY directly: has_function_privilege
     = f for all eight app roles and for PUBLIC (Part 1 §2, §3). They execute only as
     nested calls inside the two definer functions, so no principal can call them to
     "pre-book" a slot, and no principal can skip them.
  5. The advisory lock is taken INSIDE the assertion function, inside the caller's
     transaction. The API layer issues no lock statement of its own, which is what
     restores compliance with frozen 6A §17.3.
  6. The admission test is the post-insert invariant (v_active + 1) > v_hard_limit,
     not the pre-insert comparison v_active >= v_hard_limit, so it is correct for
     every value the NUMERIC(18,4) column can hold, fractional limits included
     (FAR-P1-02; proven in FAR_DB_02 §2).
  7. Entry into the counted set is therefore controlled on BOTH edges: INSERT is
     reachable only through the guarded functions, and no UPDATE can move a row
     from the uncounted set (DEPRECATED, or deleted_at IS NOT NULL) back into the
     counted set, nor move a row to another tenant (FAR-P1-03; Part 2b and
     FAR_DB_02 §7).

  Therefore: to occupy an ACTIVE_AGENTS slot, a row MUST have passed the quota
  guard, and it cannot be smuggled in afterwards. That is the difference between
  "an enforcement primitive exists" and "a compliant enforcement path is the only
  path" - the distinction DB-BLOCKER-FINAL-API-001 was raised over.
